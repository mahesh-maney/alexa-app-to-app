What is App Flip?

App Flip is Google's Android-only mechanism that skips the browser-based OAuth login. Instead of showing a web page, Google sends a direct Android intent to the Digilux app. Since the user is already logged into Digilux, they get linked without typing credentials again.

Step-by-Step Breakdown

  • 1
    User taps "Link Google Home"
    Flutter app calls our POST /deep-link/start — creates a session record with a UUID state and 30-min TTL in DynamoDB. Then opens a Google Home deep link URL.
  • 2
    Google Home sends App Flip intent
    GH app detects that the Digilux package is installed and sends an Android intent with CLIENT_ID, REDIRECT_URI, SCOPE — no browser opens.
  • 3
    Digilux app posts access token to /authorize
    The Flutter MethodChannel returns the Cognito access token. The Android Activity POSTs it to our Lambda which validates it against Cognito, then issues an auth code (900s TTL).
  • 4
    Auth code returned to Google Home app
    The Activity calls setResult(RESULT_OK) with the auth code. Google Home app receives it and forwards it to Google's cloud backend.
  • 5
    ⏳ Google Cloud calls our /token endpoint — CURRENTLY BLOCKED
    Google's backend calls POST /google-home/oauth/token to exchange the auth code for access + refresh tokens. This step is blocked by the current project-level backoff.
  • 6
    Tokens stored — linking complete
    On success our Lambda stores the token pair in google_home_tokens DynamoDB table. The Flutter app's 2-second status poll detects linked=true and updates the UI.

🗄 DynamoDB — What Gets Stored
Three tables manage the full linking lifecycle. All use on-demand billing with TTL auto-expiry.

Table 1 — google_home_link_sessions

Created when the user taps "Link Google Home". Prevents CSRF attacks. Expires after 30 minutes.

FieldTypeExamplePurpose
state 🔑String (PK)a1b2c3d4-e5f6-...UUID generated per link attempt
userIdStringf123dd2a-7061-...Cognito sub of the logged-in user
statusStringPENDINGSession state
createdAtNumber1726840000Unix timestamp
ttlNumber1726841800Auto-deleted after 1800s (30 min)

Table 2 — google_home_auth_codes

Stores the one-time auth code issued after login. Google must exchange it within 15 minutes or it expires.

FieldTypeExamplePurpose
code 🔑String (PK)ZMoYqpKc7x...32-char random auth code
userIdStringf123dd2a-7061-...Owner of this code
createdAtNumber1726840051Unix timestamp
ttlNumber1726840951Auto-deleted after 900s (15 min)

Table 3 — google_home_tokens — The Source of Truth

Written when linking succeeds. Read on every voice command. Deleted on unlink.

FieldTypeExamplePurpose
userId 🔑String (PK)f123dd2a-7061-...One record per linked user
accessTokenStringat_abc123...Short-lived token (1 hour) — GSI indexed
refreshTokenStringrt_xyz789...Long-lived token (180 days) — GSI indexed
agentIdStringdigilux-ai-proGoogle Home project ID
linkedAtString1726840055When the user first linked
expiresAtNumber1726843655When current access token expires

🚧 The Backoff — What Happened & Why
Why Google stopped calling our /token endpoint and what we observed in CloudWatch.
🔴
Root Cause

On Sept 18th at 12:42 UTC, an incorrect client_secret was temporarily set in the Google Home Developer Console. When Google called our /token Lambda, the secret didn't match what was in Secrets Manager → we returned {"error": "invalid_client"}. After multiple such errors, Google applied a project-level backoff of 24–72 hours.
